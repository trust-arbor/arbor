# Source-bound conversation interactions

Implemented host scope, 2026-10-03.

A live Session opens an opaque source handle from its private journal command claim and exact Engine generation. The Authority validates the claim and caller process, monitors the Session, and creates each durable interaction with a closed immutable attachment before admission and delivery. Engine options carry the handle outside graph values and checkpoints. Graph attributes, UserMessage metadata and action parameters cannot create an attachment.

Ordinary WaitHuman choices use Authority-issued operation IDs, revision 1, and immutable `choice_N` IDs. The answer must match the command, request, operation and revision and belong to the original choice table. Invalid answers leave the request pending. Bounded discovery lists pending prompts before deterministic terminal history, so completed prompts cannot hide the live request. Duplicate display labels remain distinct choices; the handler supplies an exact target without an ambiguous preferred label.

The first terminal transition, deadline and delivery outbox remain owned by the existing durable InteractionRegistry Authority. Answer acceptance and source retirement share that serialized owner. Session death retires pending requests. Authority restart abandons source-attached pending records with `source_lost`; neither source handles nor waiting workers are reconstructed. A winning response stores closed verified human evidence in the same durable compare-and-swap as its terminal result. Lifecycle schema 3 accepts strict version 1/2 upgrades and rejects malformed attachments or evidence.

Authenticated Agent reads and answers use an operation-bound one-use Security receipt. The Authority independently reconstructs the payload from the stored scope and closed answer, consumes the receipt, and rechecks the current proof subject, canonical chat owner and engagement. Signed proofs bind the exact request bytes; the optional engagement fence is compare-only.

Source-attached prompts never enter legacy adapter delivery. The wrapper does not wake that Dispatcher, and Authority sweep discovery and direct claims deny attached records. Scoped Agent surfaces own rendering and must authenticate each read; a separately configured operator or a revoked chat grant cannot receive a prompt through a later legacy sweep. The existing durable outbox remains for unrelated legacy interactions.

Native action approval travels through the existing private Engine option, Actions executor control and configured Security router port. A supplied invalid source fails closed instead of creating an unscoped approval. Source-attached protected records refuse raw Comms responses and ordinary choice responses. The winning approval also requires an existing general human SessionToken and an existing approval-answer capability for the original task, agent or principal. A conversation-purpose v2 token remains chat-only, including when its human has an approval-answer grant.

Native approval validates the original normalized task, agent, principal, resource and action identity before projecting durable data. The stored record preserves that identity and the original capability ID, plus bounded display text for known command, target, preview, reason and trust fields. Rich taint remains process-local authorization evidence and is omitted from durable display data; a display label never establishes a taint or authorization proof.

This slice supports ordinary unconditional outgoing choices and native approval. Source-bound conditional outgoing choices fail closed pending an explicit Router target-selection contract. Human review/declassification attributes are unsupported; neither chat labels nor callbacks reduce taint. Missing or failing interviewers fail closed. Explicit AutoApprove remains an ordinary, nonprotected test fixture.

Public Comms ports are `open_conversation_source/3`, `retire_conversation_source/2`, `request_conversation_interaction/3`, `conversation_interactions/2`, `respond_conversation_interaction/4` and `conversation_interaction_request_payload/5`. Source handles are private process-local controls, not wire values. Read projections contain only the source command identity, request/operation/revision, display text, choices and lifecycle status.

Behavioral regression coverage exercises actual Engine WaitHuman routing and real durable journal/Authority acceptance, deadline, retirement, process death and restart. Six actual Agent journeys cover signed exact-choice continuation, cancellation across generations, native Exec approval with one counted invocation, a child graph prompt attached to its parent command, and ordinary/native source Authority outages before Engine start. Authenticated read and answer envelopes correlate the exact command, engagement and operation revision.

The Agent journey fixture grants exact Engine opcode scopes (`human_interaction`, `transform`, `unknown`, native `action` and `compose`); a general `execute` grant alone does not imply these handler grants. Native retry uses the enabled existing Trust ApprovalGuard. The disabled legacy guard branch re-escalates an approved constrained capability and is not the qualified fixture mode.

Journey tests run in an isolated worktree with a real SQLite command journal and a separate real durable Security audit database, each using one connection. That qualifies serialized security behavior, not production availability or concurrent write capacity. Earlier pool-four runs exposed projector lock/deadline contention; their failing receipts are preserved separately, and concurrency qualification belongs to the Persistence acquisition boundary.
