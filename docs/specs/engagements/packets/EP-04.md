# EP-04 — ChatLive `:acp` runtime → Session ACP runtime

**Phase:** B (parallel to Phase A) · **Depends:** none (substrate steps 1–2 shipped) · **Spec:** removes `(planned)` from ENGAGE-9
**Apps:** `arbor_dashboard` (primary), possibly none other.

## Goal

CLI-model chats (Claude SDK / ACP) stop bypassing the Session: same engagement, same
transcript, same persistence as `:arbor`-runtime chats. Island 5 (chat half) closes.

## Read first

- `apps/arbor_dashboard/lib/arbor_dashboard/live/chat_live.ex` —
  `run_query(:acp, ...)` (~line 1416: unwraps the UserMessage to `um.content`,
  calls `Claude.query(agent, input, timeout: :infinity, permission_mode: :bypass)`),
  `dispatch_query/3`, `send_prompt/2` (envelope built + engagement-tagged BEFORE the
  runtime split — good, keep), and how `chat_runtime` is assigned/selected in mount
  and events (grep `chat_runtime` through the file).
- `apps/arbor_orchestrator/lib/arbor/orchestrator/session.ex` — `set_runtime/2`
  (`runtime in [:arbor, :acp]`) and its doc; `send_message/2`. Understand what the
  Session's `:acp` runtime does with a turn — find the execution-mode branch:
  `grep -n "execution_mode\|:acp" apps/arbor_orchestrator/lib/arbor/orchestrator/session.ex | head -30`
  and read the relevant clauses, plus `session_core.ex` if the branch lives there.
  **If the Session's ACP runtime turns out NOT to complete a full turn path
  (missing reply plumbing), STOP after documenting exactly what's missing — file
  that as the result instead of hacking around it.** The packet's premise is that
  `set_runtime(:acp)` is functional (it's in the public API with guards); verify
  early.
- `apps/arbor_dashboard` tests for chat runtime switching:
  `grep -rn "chat_runtime\|:acp" apps/arbor_dashboard/test --include=*.exs -l | head`.

## Deliverables

1. In ChatLive, when the user selects the ACP runtime: call
   `Session.set_runtime(session_pid_or_ref, :acp)` once on switch (resolve the pid
   the same way `live_host_pid/1` does), and route the turn through the SAME
   dispatch path as `:arbor` (`APIAgent.query` with the full engagement-tagged
   UserMessage). Delete the `run_query(:acp, ...)` clauses that unwrap to
   `Claude.query` — behind a rollback: config
   `:arbor_dashboard, :acp_chat_path` `:session` (default) | `:legacy`, honored in
   `dispatch_query/3`, documented for one release window (module doc note).
2. Runtime switch UX guard: switching runtime mid-turn queues like any message
   (Session already queues mid-turn sends); don't add bespoke locking.
3. Permission mode: the legacy path used `permission_mode: :bypass`. The Session
   ACP runtime has its own permission plumbing — do NOT thread `:bypass` through;
   note the behavioral difference in the moduledoc and result summary (approvals
   may now appear for ACP chat turns — that's correct, not a regression).
