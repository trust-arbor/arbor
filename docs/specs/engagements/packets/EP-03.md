# EP-03 — Outbound provenance + the no-new-islands canary

**Phase:** A · **Depends:** EP-02 · **Spec:** removes `(planned)` from ENGAGE-3 (outbound half), ENGAGE-18; proves ENGAGE-17
**App:** `arbor_comms` (+ one test-support module wherever the canary fits best).

## Goal

Replies carry the engagement id end-to-end, and CI permanently refuses new
conversational islands.

## Read first

- `apps/arbor_comms/lib/arbor/comms/dispatcher.ex` — the two `conversation_id:
  original.conversation_id` echo sites (replies already preserve it once inbound
  sets it — verify, don't assume) and `deliver_envelope/3`.
- `apps/arbor_comms/lib/arbor/comms/response_router.ex` — `route/2` channel
  selection; check whether ResponseEnvelope carries conversation metadata at all.
- `apps/arbor_contracts/lib/arbor/contracts/comms/response_envelope.ex` — fields.
- The entry points for the canary: `apps/arbor_dashboard/.../chat_live.ex`
  (`tag_engagement`), `apps/arbor_gateway/.../chat/socket.ex` (engagement resolve),
  `apps/arbor_comms/.../message_handler.ex` (EP-01 resolver),
  `docs/specs/voice/packets/VP-04.md` (voice — may not be merged yet; the canary
  lists it as pending-tolerated until the module exists).

## Deliverables

1. Outbound (ENGAGE-3): ensure every outbound message built from a reply to an
   engagement-resolved inbound carries `conversation_id` — trace
   `Dispatcher.reply/2` and `deliver_envelope/3` paths; fix any branch that builds
   an outbound Message without copying it. If `ResponseEnvelope` needs a
   `conversation_id` passthrough field, add it (contracts touch is allowed here;
   keep it optional/nil-default).
2. Turn signal: after a successful engagement-resolved reply delivery, emit
   `Arbor.Signals.emit(:comms, :engagement_turn, %{engagement_id:, channel:,
   direction: :outbound}, scope: :cluster)` (mirror the existing emit style in
   `dispatcher.ex`).
3. Canary (ENGAGE-18/17): a `:behavioral`-or-`:integration`-tagged test module
   `engagement_islands_canary_test.exs` that:
   - enumerates a declared list of entry-point modules + the function evidencing
     engagement resolution (module attribute list with
     `{module, function_name_string}` pairs);
   - asserts each module's source contains the resolution call (source-grep
     assertions are acceptable and cheap: `File.read!` + regex on
     `resolve_or_create|with_engagement`) AND that the module exists;
   - carries a loud comment: adding a conversational entry point requires adding it
     here, and the PR that adds an entry point without engagement resolution must
     fail this test. Include a `pending` mechanism for not-yet-merged surfaces
     (voice) that flips to enforced when the module appears.

## Tests

- `@tag spec: "ENGAGE-3"` — end-to-end through MessageHandler with a fake channel
  sender: inbound resolves engagement → generator replies → captured outbound has
  the same `conversation_id`.
- `@tag spec: "ENGAGE-18"` — the canary itself (tag the canary test with this id).
- `@tag spec: "ENGAGE-17"` — canary also asserts no module outside EngagementStore
  defines a competing conversation registry: grep-assert that
  `resolve_or_create` call sites all target `Arbor.Comms.EngagementStore`.

## Acceptance

`./bin/mix compile --warnings-as-errors`; comms suite green; canary green with
voice listed as pending.

## Out of scope

New adapters, broadcast-to-all-attached reply policy (stays echo-to-origin),
interaction recording (EP-08).
