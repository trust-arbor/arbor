# EP-02 — Session-backed responder; retire the shared CLI session

**Phase:** A · **Depends:** EP-01 · **Blocks:** EP-03, EP-06 · **Spec:** removes `(planned)` from ENGAGE-5, ENGAGE-6 (construction half), ENGAGE-7
**Apps:** `arbor_agent` (new responder), `arbor_comms` (startup validation only), config.

## Goal

External-adapter messages get answered by the user's actual agent through its
Session — engagement-tagged, transcript-persisted, per-engagement context — instead
of the shared-file CLI session. The worst island dies here.

## Read first

- `apps/arbor_ai/lib/arbor/ai/comms_responder.ex` — the legacy generator you are
  replacing: `generate_response/2` return contract (`{:ok, ResponseEnvelope}`),
  `extract_channel_hint/1` channel-intent parsing (KEEP this behavior — port it),
  and the session-file mechanics you are killing.
- `apps/arbor_contracts/lib/arbor/contracts/comms/response_generator.ex` — the
  behaviour (note its moduledoc: the seam exists precisely so comms has no direct
  dep on the brain).
- `apps/arbor_agent/lib/arbor/agent/api_agent.ex` — `query/3`: accepts a
  `UserMessage`, resolves the agent's session pid, does
  `GenServer.call(session_pid, {:send_message, message}, timeout)` — this is your
  whole bridge; copy its pid-resolution and timeout handling.
- `apps/arbor_dashboard/lib/arbor_dashboard/live/chat_live.ex` —
  `find_agent_for_session/1` (`Manager.find_first_agent` /
  `find_agent_for_principal`) for agent selection precedent.
- `docs/arbor/CODING_TASK_DISPATCH.md` — the `ARBOR_CODING_EXECUTOR=legacy`
  rollback pattern (env validated at startup, fail-closed on invalid values); and
  find its validation implementation:
  `grep -rn "ARBOR_CODING_EXECUTOR" apps --include=*.ex | grep -v test`.

## Deliverables

1. `Arbor.Agent.Comms.SessionResponder`
   (`apps/arbor_agent/lib/arbor/agent/comms/session_responder.ex`),
   `@behaviour Arbor.Contracts.Comms.ResponseGenerator`:
   - `generate_response(msg, context)`:
     a. Agent: `context[:agent_id]` if present, else the ChatLive-precedent default
        (per-user lookup when `context[:user_id]` maps to a principal; else
        first-agent fallback).
     b. Build `UserMessage` with the transport constructor conventions: content
        `msg.content`, `transport: context[:transport]`, `sent_at` from
        `msg.received_at` when set, `sender_id: context[:user_id] || msg.from`,
        then `with_engagement(context[:engagement_id])` when present.
     c. Deliver via the APIAgent.query mechanism (pid + `{:send_message, ...}` —
        no orchestrator module reference).
     d. Port `extract_channel_hint/1` from the legacy responder (same regex, same
        allowed channels) and return `{:ok, ResponseEnvelope.new(body: body,
        channel: channel)}`.
     e. Errors: mirror the legacy responder's error contract
        (`{:error, reason}`; empty reply → `{:error, :empty_response}`).
   - NO session file. NO `Arbor.AI.generate_text`. The Session owns all context.
2. Config flip + rollback (ENGAGE-7):
   - `config :arbor_comms, :handler` `response_generator:` →
     `Arbor.Agent.Comms.SessionResponder` in the default config.
   - `ARBOR_COMMS_RESPONDER` env: unset/`session` → new module; `legacy` →
     `Arbor.AI.CommsResponder`. Implement validation exactly like the coding
     executor selector (raw value stored at runtime-config time, validated at
     startup by the app that owns the children, invalid value fails startup).
     Document the selector in `docs/arbor/CODING_TASK_DISPATCH.md`-style prose
     inside the module doc + a note in `apps/arbor_comms/README.md` if one exists.
   - Deprecation header on `Arbor.AI.CommsResponder` (`@moduledoc` note +
     `Logger.warning` once at first use) — do not delete it.
3. Cross-sender isolation proof (the point of it all): see tests.

## Tests

- `@tag spec: "ENGAGE-5"` — with a fake session target (test GenServer accepting
  `{:send_message, %UserMessage{}}`), `generate_response/2` delivers an
  engagement-tagged envelope and returns its reply as the ResponseEnvelope body.
- `@tag spec: "ENGAGE-6"` — the built UserMessage has the context transport and the
  platform `sent_at`.
- `@tag spec: "ENGAGE-7"` — (a) two messages with different `engagement_id`s hit
  the session with DIFFERENT engagement tags (no shared context key anywhere);
  (b) the module never touches `~/.arbor/comms-session-id` (assert file untouched
  in tmp-HOME test env); (c) selector: `legacy` env → legacy module chosen,
  invalid env value → startup validation error (mirror the executor-selector test —
  find it: `grep -rn "ARBOR_CODING_EXECUTOR" apps --include=*_test.exs`).
- Channel-hint port: parametrized tests copied from any existing CommsResponder
  hint tests (find them) — `[CHANNEL:email]` prefix routes and strips.

## Acceptance

`./bin/mix compile --warnings-as-errors`; agent + comms suites green; manual smoke
documented in result summary: with the node running and a real agent, a Signal
message produces a reply AND the turn appears in the dashboard transcript for that
user's engagement (this is the Phase A payoff).
