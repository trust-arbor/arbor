# EP-06 — Memory provenance: stamp engagement_id on engagement-born entries

**Phase:** C · **Depends:** EP-02 (so adapter turns carry engagements) · **Blocks:** EP-07 · **Spec:** removes `(planned)` from ENGAGE-12
**Apps:** `arbor_memory` and/or `arbor_orchestrator` (where memory writes happen — the Read-first determines which).

## Goal

Every memory entry created from an engagement-tagged turn records WHERE it was
learned. Pure provenance stamping — no behavior change to storage or recall (the
gate is EP-07).

## Read first

- Find where turn content becomes memory: start from
  `apps/arbor_orchestrator/lib/arbor/orchestrator/session/persistence.ex` and the
  Session turn pipeline —
  `grep -rn "Memory\.\|arbor_memory\|remember\|store_memory" apps/arbor_orchestrator/lib --include=*.ex | head -15`,
  then read the memory-write call sites and the `arbor_memory` API they use
  (`grep -n "def " apps/arbor_memory/lib/arbor/memory.ex | head -30`).
- How the Session knows the current engagement:
  `current_engagement_id` in session state
  (`grep -n "current_engagement_id" apps/arbor_orchestrator/lib/arbor/orchestrator/session.ex`).
- Memory entry schema/metadata shape: find the entry struct/schema in
  `arbor_memory` (+ its persistence) and confirm there's a metadata map to extend —
  do NOT add a new column/field if a metadata map exists.
- The single-mind model rationale: `.arbor/roadmap/2-planned/channels-as-engagements.md`
  §"Clarified direction" + §"Audience / visibility" — memory stays unified
  per-agent; provenance is a stamp, not a partition.

## Deliverables

1. Thread the source engagement id from the turn context into every memory write
   that originates from conversational turns (working-memory promotions, episodic
   writes, whatever the call sites are — enumerate what you found in the result
   summary). Mechanism: extend the memory-write API's opts/metadata with
   `source_engagement_id` (nil-safe; absent for non-conversational writes like
   heartbeat reflections — stamp those only if a current engagement is active in
   the turn that produced them).
2. Persistence: the stamp must survive round-trip (write → read shows it) in
   whatever metadata slot the schema offers.
3. No recall change. No new indexes unless reading the stamp requires one (it
   shouldn't yet).

## Tests

- `@tag spec: "ENGAGE-12"` — a turn with `current_engagement_id` set produces
  memory entries whose stored metadata carries that id (integration-style through
  the real write path with fakes only at the LLM boundary); a
  non-engagement turn produces entries without the stamp; round-trip read shows it.
- Regression: existing memory tests unaffected (the opts are additive).

## Acceptance

`./bin/mix compile --warnings-as-errors`; memory + orchestrator suites green;
result summary lists every write call site found and stamped (this list is EP-07's
input — be exhaustive).

## Out of scope

Recall gating (EP-07), backfilling legacy entries, visibility lookups.
