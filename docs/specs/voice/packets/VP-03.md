# VP-03 — xAI Realtime backend (extract from prototype)

**Phase:** 1 · **Depends:** VP-02 · **Blocks:** VP-04 · **Spec:** VOICE-6, VOICE-8 (partial), removes nothing planned
**App:** `arbor_voice`.

## Goal

`Arbor.Voice.Backend.XaiRealtime` implements `Arbor.Voice.RealtimeBackend` by
extracting the proven protocol code from the prototype. The prototype stays in place
(it still works standalone) — this packet copies/adapts, it does not delete.

## Deliverables

1. `Arbor.Voice.Backend.XaiRealtime` (`apps/arbor_voice/lib/arbor/voice/backend/xai_realtime.ex`):
   - `open/1`: resolve token via `Arbor.LLM.OAuth.access_token(:xai)` (opts may
     override host/path for tests), connect exactly as the prototype does. The token
     MUST NOT appear in logs, error tuples, or the session struct's `inspect` output
     (use `@derive {Inspect, except: [...]}` or keep it out of the struct).
   - `configure/2`: build the session.update from the behaviour's map — instructions,
     tools (pass through as `session.tools`), audio config defaulting to the
     prototype's proven nested shape when `:audio` is present; text-only otherwise
     (`modalities: ["text"]`).
   - `send_text/2`, `send_audio/2`, `send_tool_result/3`: prototype's `user_text/1`,
     `send_audio/2`, `function_output/2` respectively (each followed by
     `response.create` exactly as the prototype sequences them).
   - `recv/2`: pump one event, mapping wire types to behaviour events:
     `conversation.item.input_audio_transcription.completed` → `{:input_transcript, text}`;
     `response.output_audio.delta` → `{:output_audio, pcm}` (base64-decoded);
     `response.output_audio_transcript.delta` and text deltas → `{:output_text_delta, s}`;
     `response.function_call_arguments.done` → `{:tool_call, %{id, name, arguments}}`
     (JSON-decode arguments; malformed arguments produce `{:error, {:bad_tool_args, name}}`
     event, not a crash);
     `response.done` → `{:turn_done, %{text: accumulated}}` (accumulate deltas inside
     the session term like the prototype's `acc`); `error` → `{:error, payload}`.
     Unknown event types are skipped (recurse), as in the prototype.
   - `close/1`, `meta/1` (`%{backend: :xai_realtime, mode: :cloud, input_rate: 16_000,
     output_rate: 24_000}`).
2. **Transport seam for tests:** extract the socket operations the prototype does
   directly (upgrade/send/recv frame) behind a private module
   `Arbor.Voice.Backend.XaiRealtime.Transport` with a `@behaviour`-less contract of
   3-4 functions, selected via opts (`transport: FakeTransport`). Default is the real
   Mint implementation. Keep it minimal — this exists so `recv/2` event mapping is
   unit-testable from scripted frames.

## Tests (all `:fast`, no network)

Using a scripted `FakeTransport` feeding recorded-shape JSON frames (copy literal
event shapes from the prototype's `handle/4` doc/patterns):

- `@tag spec: "VOICE-8"` — a `function_call_arguments.done` frame yields
  `{:tool_call, ...}`; `send_tool_result/3` emits `function_call_output` +
  `response.create` (assert on frames the fake captured); malformed tool args yield
  the structured error event.
- `@tag spec: "VOICE-6"` — token never appears in `inspect(session)` nor in any
  frame logged/captured except the upgrade header; `open/1` with a failing OAuth
  resolver returns `{:error, _}` without raising.
- Event-mapping table test: each wire type above maps to the documented event.
