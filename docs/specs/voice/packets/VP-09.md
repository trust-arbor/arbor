# VP-09 — Voice approvals: `ChannelAdapter` for HITL

**Phase:** 3/4 · **Depends:** VP-04 (may run parallel to VP-07/08) · **Spec:** VOICE-18, VOICE-19, VOICE-20; VOICE-16 applies
**App:** `arbor_voice` (+ one config line in comms config).

## Goal

Approve low-risk agent actions by voice with an explicit confirmation phrase;
everything above the voice ceiling escalates to the screen.

## Read first

- `apps/arbor_contracts/lib/arbor/contracts/comms/channel_adapter.ex` — the ENTIRE
  behaviour (`send_interaction/2`, `parse_response/1` with the three-way
  `parse_result`, `channel_kind/0`).
- `apps/arbor_comms/lib/arbor/comms/interaction_router.ex` — `request/2`,
  `respond/3`, the adapter-map config key
  (`config :arbor_comms, :interaction_adapters, %{...}`), and presence routing.
- `apps/arbor_comms/lib/arbor/comms/channels/signal/interaction_adapter.ex` — the
  existing non-dashboard adapter; copy its structure (formatting, partial-response
  handling, disambiguation reply).
- `apps/arbor_contracts/lib/arbor/contracts/comms/interaction.ex` — the Interaction
  struct (fields: `request_id`, `kind`, `agent_id`, `user_id`, `description`,
  `resource_uri`, `urgency`, `metadata`, `expires_at`, `response_topic`,
  `submitted_at`). For the ceiling check, derive the effect class from
  `resource_uri`/`metadata` — grep `effect_class` in `arbor_contracts`
  (`security/classification.ex`, `security/capability_profile.ex`) and
  `arbor_actions` to find the canonical classification helper; VOICE-19 keys off it.

## Deliverables

1. `Arbor.Voice.InteractionAdapter` (`apps/arbor_voice/lib/arbor/voice/interaction_adapter.ex`),
   `@behaviour Arbor.Contracts.Comms.ChannelAdapter`, `channel_kind: :voice`:
   - `send_interaction(user, interaction)`:
     a. **Ceiling check (VOICE-19):** determine the request's effect class (from the
        interaction/its metadata — per your Read-first grep). Config
        `:arbor_voice, :approval_ceiling` lists speakable classes, default
        `[:read, :local_write]`. Above ceiling → do NOT speak content: speak (via
        the VoiceSession TTS path, Speakable-rendered) "An approval is waiting on
        your screen." and return `:ok` (the router's dashboard adapter handles the
        real prompt; if the router requires an explicit fallback signal, follow
        what the Signal adapter does for undeliverable).
     b. Within ceiling: generate a confirmation word (two random short words from a
        fixed wordlist, e.g. "maple-seven"), store `{request_id, word, expires_at}`
        in the adapter's ETS (Registry-owned table, 5 min TTL), and speak a compact
        summary: action, target, blast radius, then "Say: confirm <word> — or deny."
        The summary string goes through `Speakable.render/2` and VOICE-16's gate.
   - `parse_response(raw)` (raw = `%{user_id:, text:}` from the voice loop — the
     VoiceSession feeds every user utterance through this BEFORE treating it as a
     conversation turn; wire that call into `Arbor.Voice.Session.text_turn/2` at the
     top):
     - text matches `confirm <word>` (case/punct-insensitive) with a live stored
       word → `{:interaction_response, request_id, :approved, %{channel: :voice}}`
       and clear the entry. (VOICE-18: the word is required — implement NO bare-yes
       clause.)
     - "deny"/"reject" + exactly one live entry → that request's denial with the
       full id form.
     - "deny" with multiple live entries → `{:interaction_response_partial, :denied, %{}}`
       (router disambiguates, VOICE-20); the adapter's disambiguation reply lists
       pending ids/words by speaking them (follow the Signal adapter's pattern).
     - anything else → `:not_interaction`.
2. Registration: add `voice: Arbor.Voice.InteractionAdapter` to the
   `:interaction_adapters` map in the comms config (dev/prod config files — find
   where the dashboard adapter is registered and mirror it). Presence: register
   voice presence with `PresenceTracker` on VoiceSession start / deregister on stop
   (grep how the dashboard/Signal presence registers; mirror).

## Tests

- `@tag spec: "VOICE-18"` — "yes"/"approve"/"do it" with a live request →
  `:not_interaction`; "confirm <word>" → the response tuple; wrong word →
  `:not_interaction`; expired word → `:not_interaction`.
- `@tag spec: "VOICE-19"` — an interaction with effect class outside the ceiling
  never has its content in any spoken string (capture via fake TTS sink); a
  within-ceiling one does, Speakable-rendered.
- `@tag spec: "VOICE-20"` — multi-pending partial denial returns the partial tuple;
  the disambiguation speech lists all pending.
- Integration (`:integration`): full round-trip through the real
  `InteractionRouter.request/2` + `respond/3` with the adapter registered in a
  test adapter-map (router has an `:adapter_map` test override — use it).

## Acceptance

`./bin/mix compile --warnings-as-errors`; tests green; config registration present
but the adapter only activates when a VoiceSession registers presence (no impact on
existing routing when voice is idle — prove with a router test where voice has no
presence).
