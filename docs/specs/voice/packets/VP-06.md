# VP-06 — Speakable renderer + sensitivity gate

**Phase:** 1 · **Depends:** VP-02 · **Blocks:** VP-04 · **Spec:** VOICE-13, VOICE-14, VOICE-15, VOICE-16
**App:** `arbor_voice`.

## Goal

A pure, deterministic module that converts any assistant/notification text into a
speakable form, and the single gate deciding "may this be spoken at all?".

- `docs/specs/voice/VOICE-1.0.md` §Speakable rendering

## Deliverables

`Arbor.Voice.Speakable` (`apps/arbor_voice/lib/arbor/voice/speakable.ex`), pure
functions only:

```elixir
@type verdict ::
        {:speak, String.t()}                     # safe, within budget
      | {:speak_truncated, String.t()}           # budgeted summary; full text is on screen
      | {:screen_only, String.t()}               # spoken form is a non-specific pointer
@spec render(String.t(), keyword()) :: verdict()
# opts: :max_words (default 60), :classifier (arity-1 fun -> :public | :internal |
#       :confidential | :restricted; default resolves the real classifier),
#       :escalation_phrase (default "the rest is on your screen")
```

Rules, in order:

1. **Sensitivity gate first** (VOICE-16): classifier says `:confidential` or
   `:restricted` → `{:screen_only, "That's sensitive — I've put it on your screen."}`.
   Classifier errors/timeouts fail CLOSED to `:screen_only`.
2. **Shape stripping** (VOICE-14): remove fenced code blocks, markdown tables,
   URLs (`http(s)://…` → drop the URL, keep surrounding sentence), base64/hex blobs
   (>40 chars of [A-Za-z0-9+/=]), and markdown link syntax (keep link text). If
   stripping removed content, the result is at best `:speak_truncated`.
3. **Budget** (VOICE-14/15): if the stripped text exceeds `:max_words`, cut at the
   last sentence boundary under budget and append the escalation phrase →
   `{:speak_truncated, ...}`. Lists with >5 items become "N items — first three: …".
4. Otherwise `{:speak, text}`.

Also: `Arbor.Voice.Speakable.tts_guard!/1` — raises unless given a `{:speak, _}` or
`{:speak_truncated, _}` verdict result string; VP-04/07/08 route every TTS call
through the verdict so no call site can bypass rendering (VOICE-13 is proven at those
call sites; note it in the moduledoc).

## Tests (all `:fast`, table-driven)

- `@tag spec: "VOICE-14"` — code block / table / URL / base64 never appear in any
  verdict's speakable string; word budget enforced at sentence boundary.
- `@tag spec: "VOICE-15"` — truncated verdicts end with the escalation phrase.
- `@tag spec: "VOICE-16"` — `:restricted`/`:confidential` → `:screen_only`;
  classifier crash → `:screen_only` (fail closed).
- Property-ish sanity: `render/2` is deterministic and total for arbitrary printable
  strings (no raises).

## Acceptance

`./bin/mix compile --warnings-as-errors`; tests green; module has zero runtime deps
beyond stdlib + the classifier resolution (documented).

## Out of scope

LLM-based summarization (future flag), TTS itself, notification queue.
