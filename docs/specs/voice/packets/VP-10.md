# VP-10 — Operator loop: notification queue + status/dispatch tools

**Phase:** 4 · **Depends:** VP-05 (VP-08 for the phone path to matter) · **Spec:** removes `(planned)` from VOICE-12, VOICE-29, VOICE-30, VOICE-31
**App:** `arbor_voice`.

## Goal

Dispatch work by voice, walk away, get told when it finishes, ask "what's running?"
— the async supervisor loop from the plan.

## Read first

- `docs/arbor/CODING_TASK_DISPATCH.md` — the structured `coding_change` plan
  envelope, status/result/approval flow.
- Locate the internal dispatch/status facade the MCP tools wrap:
  `grep -rn "arbor_dispatch_task\|arbor_task_status" apps/arbor_gateway/lib --include=*.ex`
  then follow to the module it calls (expected: an `arbor_agent`-owned task facade —
  the roadmap records "TaskStore owns the mailbox … `arbor_agent` concern"). Use THAT
  facade; `arbor_voice` deps `arbor_agent` already (VP-02).
- `apps/arbor_voice/lib/arbor/voice/{session,tools,speakable}.ex`.
- Signals facade in `arbor_signals` (how to subscribe — grep `subscribe` usage in
  `apps/arbor_comms/lib` for the canonical pattern) and what task-completion signals
  exist: `grep -rn "task.completed\|task_completed\|signal" apps/arbor_agent/lib --include=*.ex | grep -i "task" | head`.
  If no completion signal exists, poll the status facade (5 s tick) and note the gap.

## Deliverables

1. `Arbor.Voice.NotificationQueue` (`.../notification_queue.ex`) — GenServer owned by
   the VoiceSession supervisor tree:
   - `notify(server, %{priority: :urgent | :normal | :low, source: atom(),
     summary: String.t(), sensitive: boolean(), ref: term()})`
   - Ordered FIFO within priority; `:urgent` preempts order but NEVER interrupts
     in-flight TTS (VOICE-29): the queue drains only when the VoiceSession reports
     idle (a `notify_when_idle` hook on the session; add it — the session calls
     `Queue.session_idle/1` after each completed turn and after TTS playback).
   - Batching: `:low`/`:normal` items arriving during an active conversation window
     (config, default 120 s since last user turn) accumulate; on drain, speak a
     batch summary ("3 updates: …") rather than N utterances.
   - `sensitive: true` (VOICE-30): the spoken form is source + "details on your
     screen" only; the summary body is recorded to the engagement transcript
     (recorder from VP-04) but never spoken (Speakable's gate applies anyway —
     belt and suspenders).
2. Dispatch tool (VOICE-12): extend `Arbor.Voice.Tools.declarations/0` with
   `dispatch_coding_task` (`%{task: string, repo: string}` — repo must be one of the
   configured allowlist `:arbor_voice, :dispatch_repos`; reject otherwise — tainted
   input never picks arbitrary paths, VOICE-17 discipline). Handler: build the
   version-1 plan envelope per CODING_TASK_DISPATCH.md, call the dispatch facade,
   return "Dispatched — I'll tell you when it's done" + task_id; subscribe the
   NotificationQueue to that task's completion (signal or poll). Completion notifies
   with priority `:normal`, summary from the result's normalized outcome
   (`change_committed` / `validation_failed` / …), `sensitive: false`.
3. Status tool (VOICE-31): `list_my_tasks` tool → the status facade's data for tasks
   this session dispatched (track ids in session state) + any facade-supported
   listing; the tool output is the FACADE data serialized compactly — the model
   summarizes for speech, but the tool result is grounded (test asserts the output
   contains only facade-derived fields).
