# VP-04 — VoiceSession: engagement resolution + transcript recording

**Phase:** 1 · **Depends:** VP-03, VP-06 · **Blocks:** VP-05 · **Spec:** VOICE-2, VOICE-3, VOICE-4, VOICE-5 (complete), VOICE-7, VOICE-22, VOICE-23 (session-cue half), VOICE-24
**App:** `arbor_voice`.

## Goal

The per-user voice session process: owns one backend session, resolves the shared
engagement, records every turn durably, enforces the minute budget, and audits its
lifecycle. After this packet a text-driven voice conversation is fully
engagement-native (visible in ChatLive after reload).

## Deliverables

1. `Arbor.Voice.Session` (`apps/arbor_voice/lib/arbor/voice/session.ex`) — GenServer,
   registered via `Arbor.Voice.Registry` under `{:user, user_id}`:

   ```elixir
   # start_link(opts): :agent_id (required), :user_id (default Arbor.Voice.Config.user_id/0),
   #   :backend (module, default Config.backend_module/0), :backend_opts,
   #   :instructions (system prompt for the front-desk model), :tools (VP-05 supplies; default []),
   #   :minute_budget_ms (default from config :arbor_voice, :daily_minute_budget)
   # Public API:
   #   text_turn(server, text)  -> {:ok, %{reply: String.t(), verdict: Speakable.verdict()}} | {:error, term()}
   #   status(server)           -> map (engagement_id, backend meta, turns, elapsed_ms, budget_remaining_ms)
   #   stop(server)             -> :ok
   ```

   `init/1`: resolve engagement per VOICE-2 (exact ChatLive arguments); open+configure
   the backend (`meta/1` drives the VOICE-23 session-start audit signal:
   `voice.session.started` with `%{backend:, mode:}`); trap exits.
   `terminate/2`: backend `close/1` + `voice.session.stopped` signal (VOICE-7/22).
   `text_turn/2`: send_text → recv-loop until `{:turn_done, %{text: reply}}`
   (tool_call events are handed to the tool router — a no-op returning a structured
   "no tools installed" output until VP-05, still round-tripping per VOICE-8) →
   `Speakable.render(reply)` → record turn (below) → return.
2. `Arbor.Voice.TranscriptRecorder` (`.../transcript_recorder.ex`):
   `record_turn(agent_id, engagement_id, user_msg :: UserMessage.t(), reply :: String.t(), extras :: map())`
   — appends TWO SessionStore entries (user + assistant) with the exact
   `Session.Persistence` shape, `metadata` merged with
   `%{"engagement_id" => engagement_id, "transport" => "voice"}` plus `extras`
   (e.g. delegations later). Resolve the agent's session UUID the same way the
   restore path does (from your "Read first" findings). Recording failures log a
   warning and emit `voice.transcript.record_failed` — they do not fail the turn.
   The user side uses `UserMessage.from_voice/2` (VP-01) + `with_engagement/2`.
3. Turn signal (VOICE-4): emit `voice.turn.completed`
   `%{engagement_id, backend, duration_ms}` via the signals facade after each turn.
4. Minute budget (VOICE-24): accumulate wall-clock of open backend time; on
   exceeding the budget, speak nothing, close the backend, emit
   `voice.budget.exhausted`, and have `text_turn` return `{:error, :budget_exhausted}`.
   Budget state may be process-local for now (per-day durability is a marked TODO
   comment referencing VOICE-24 — do not build persistence for it here).

- `@tag spec: "VOICE-24"` — with a tiny budget, the second turn returns
  `{:error, :budget_exhausted}` and the backend was closed.
- `@tag spec: "VOICE-8"` — a scripted tool_call before VP-05 still gets exactly one
  structured `send_tool_result` (the "no tools installed" output).
