# VP-05 — Front-desk tools: `consult_agent` + `delegate_to_agent`

**Phase:** 1 · **Depends:** VP-04 · **Blocks:** VP-07, VP-10 · **Spec:** VOICE-9, VOICE-10, VOICE-11, VOICE-17
**App:** `arbor_voice`.

## Goal

The voice front-desk model can (a) converse with the user's actual Arbor agent —
memory and all — and (b) dispatch a CLI coding agent over ACP, with progress cues.

## Read first

- `apps/arbor_agent/lib/arbor/agent/prototypes/xai_voice_orchestrator.ex` —
  `run_acp/3`, `acp_provider/1`, `mint_delegate_agent/0`, `grant_acp_caps/1`, and the
  `@tool_name` declaration in `base_session/0` (the exact tool JSON schema that
  worked live).
- `apps/arbor_ai/lib/arbor/ai.ex` — `acp_start_session/2`, `acp_create_session/2`,
  `acp_send_message/3`, `acp_close_session/1` signatures and docs.
- `apps/arbor_dashboard/lib/arbor_dashboard/live/chat_live.ex` — `run_query` for the
  `:arbor` runtime (how a UserMessage reaches the live Session process) and
  `live_host_pid/1` (`BranchSupervisor.host_pid(agent_id)` resolution + fallback).
- `apps/arbor_orchestrator/lib/arbor/orchestrator/session.ex` — `send_message/2`
  doc (blocking call, queued mid-turn, accepts the typed envelope).

## Deliverables

1. `Arbor.Voice.Tools` (`apps/arbor_voice/lib/arbor/voice/tools.ex`):
   - `declarations/0` — backend-native tool schemas (copy the prototype's
     `delegate_to_agent` schema; add `consult_agent` with
     `%{message: string}`), returned in the shape `RealtimeBackend.configure/2`
     passes through.
   - `handle(name, args, ctx)` → `{:ok, output_string} | {:error, structured}`
     where `ctx` carries `agent_id`, `engagement_id`, `user_id`, and a
     `progress_fn` (arity-1).
   - `consult_agent` (VOICE-9): build
     `UserMessage.from_voice(args["message"], transport_metadata: %{via: "front_desk"})`
     → `with_engagement(engagement_id)` → resolve host pid exactly as ChatLive's
     `live_host_pid/1` does → `Arbor.Orchestrator.Session.send_message(pid, msg)` →
     return the reply text. The transcript double-write question: `send_message`
     already persists this turn with the engagement id (that's why VoiceSession's
     recorder MUST NOT also record consult_agent turns — pass
     `record: false` back to the caller via the output tuple metadata; VP-04's
     recorder skips when the turn's only content was a consult_agent round-trip).
   - `delegate_to_agent` (VOICE-10, VOICE-17): promote the prototype's `run_acp/3`
     (provider mapping, delegate-agent mint + capability grants, close-on-exit via
     `after`). The task string is tainted user speech — pass it to ACP as the prompt
     ONLY; never interpolate it into capability URIs, agent ids, or shell strings.
     Return a compact outcome summary; include `%{delegations: [...]}` in the output
     metadata so the recorder stores it (VOICE-10 second half).
2. Wire into `Arbor.Voice.Session` (VP-04's no-op router): configure the backend
   with `Tools.declarations()`; on `{:tool_call, ...}` run
   `Tools.handle/3` under `Task.async` with the progress cue: if the task exceeds
   the configured threshold (default 2000 ms), call `progress_fn` once (VP-04 maps
   it to a short spoken filler via the backend `send_text`... NO — progress must not
   create a model turn: emit signal `voice.tool.progress` and, when audio output
   exists (VP-07+), an earcon; for now signal only). Always send exactly one
   `send_tool_result` (VOICE-8), including on task crash (structured error output).

## Tests

FakeBackend + a fake ACP facade seam (app-env-resolved module, same pattern as
VP-04's store seam) + a fake Session target (a test GenServer accepting
`send_message`):

- `@tag spec: "VOICE-9"` — consult_agent posts the engagement-tagged envelope to the
  resolved pid and returns its reply; the no-double-record contract holds (recorder
  seam sees zero writes for that turn).
- `@tag spec: "VOICE-10"` — delegate_to_agent calls acp_* in order
  (start/create/send/close) even when send fails; delegation summary lands in the
  recorded turn extras (recorder seam).
- `@tag spec: "VOICE-11"` — a slow tool (fake sleeps past threshold) produces exactly
  one `voice.tool.progress` signal; a fast one produces none.
- `@tag spec: "VOICE-17"` — a task string containing `arbor://…`, shell metachars, or
  a fake capability grant phrase reaches ACP verbatim as prompt text and appears
  NOWHERE else (assert the fake ACP saw it only in message content; assert no
  capability API was called with it).
- Tool crash → structured error `send_tool_result`, session survives.
