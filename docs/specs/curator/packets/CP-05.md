# CP-05 — Process pipeline: hourly fetch + assess, caps, cron

**Phase:** 1 · **Depends:** CP-03, CP-04 · **Blocks:** — · **Spec:** CURATE-22 (process third), CURATE-23 (process third)
**App:** `arbor_scheduler` (pipeline + caps + cron), config.

## Goal

The backlog processes itself hourly: queued items are fetched, fetched items are
assessed, under a least-privilege signed manifest.

## Read first

- `apps/arbor_scheduler/priv/pipelines/curator_intake.dot` (CP-02) — your house
  style for curator pipelines.
- How actions map to capability URIs at exec-authorization time — grep how
  `web_browse`/`web_snapshot` (`arbor://net/http`, per the `Arbor.Actions.Web`
  moduledoc) and `ai_generate_text` (`arbor://ai/generate`, per the
  `Arbor.Actions.AI` moduledoc) declare/are checked, then confirm what URIs the two
  curator actions actually require at runtime. The manifest must list exactly
  those — no more.
- `apps/arbor_scheduler/lib/mix/tasks/arbor.scheduler.sign_caps.ex` — signing.
- An existing pipeline test under `apps/arbor_scheduler/test/arbor/pipelines/`.

## Deliverables

1. `apps/arbor_scheduler/priv/pipelines/curator_process.dot` — start →
   exec `curator_fetch_batch` → exec `curator_assess_batch` → done. Batch sizes via
   node params (default 10). Header comment: purpose, cron line, manual
   `Arbor.Scheduler.enqueue_pipeline/1` invocation, and the operator sign-caps step.
2. `curator_process.caps.json` — exactly the URIs the two actions require (expected:
   the net-http egress URI for fetch and the ai-generate URI for assessment —
   confirm per Read first; CURATE-23). No shell, no fs, no coding capabilities.
3. Crontab entry (`:arbor_scheduler, Oban` crontab):
   `{"0 * * * *", Arbor.Scheduler.Workers.PipelineRunner, args: %{"pipeline_path" => "apps/arbor_scheduler/priv/pipelines/curator_process.dot"}}`
   (CURATE-22).

## Tests

- Pipeline test (house pattern) with the CP-03 snapshot seam and CP-04 LLM seam
  faked: enqueueing `curator_process.dot` moves a seeded `queued` item →
  `assessed`. `@tag spec: "CURATE-22"`.
- `@tag spec: "CURATE-23"` — assert the parsed `curator_process.caps.json` grants
  only the expected resource URIs (read the JSON in the test; fails if someone
  broadens it later). Same assertion style for `curator_intake.caps.json` if CP-02
  didn't already add it.

## Acceptance

`./bin/mix compile --warnings-as-errors`; tests green;
`./bin/mix arbor.pipeline.validate apps/arbor_scheduler/priv/pipelines/curator_process.dot`
passes. Result summary lists the exact URIs in the manifest and the file:line
justifying each.

## Out of scope

Digest (CP-06). Any change to the curator actions themselves — if the exec
authorization path demands action-side changes, stop and report (that belongs in
CP-03/CP-04 rework, not here).
