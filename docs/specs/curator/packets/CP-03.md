# CP-03 — Fetch: `curator_fetch_batch` action + content preparation

**Phase:** 1 · **Depends:** CP-02 (shared `actions/curator.ex`) · **Blocks:** CP-05 · **Spec:** CURATE-9, CURATE-10, CURATE-11, CURATE-12
**App:** `arbor_curator`, `arbor_actions`.

## Goal

Queued items get their page content fetched — through Arbor's SSRF-checked snapshot
action, never a new HTTP path — truncated, and stored; failures retry and then park
as `failed` without poisoning the batch.

## Read first

- `apps/arbor_actions/lib/arbor/actions/web.ex` — `Snapshot` submodule top to
  bottom: params (`url`, `include_*`, `max_content_length`), result shape
  (`title`, `content`, …), `Web.validate_url/1` (the SSRF gate), `effect_class/0`,
  `egress_tier/2`, `egress_destination/2`, `output_taint/0`.
- How exec authorization consumes `effect_class`/`egress_tier`/`egress_destination`
  — grep those function names under `apps/arbor_orchestrator/` and
  `apps/arbor_security/` and read the authorization call path before deciding how
  the batch action declares itself (see Deliverable 2).
- `apps/arbor_orchestrator/lib/arbor/orchestrator/session/persistence.ex` — grep
  `session_store_module` for the app-env seam pattern to copy for the snapshot seam.
- `apps/arbor_curator/lib/arbor/curator/store.ex` (CP-01) — `next_queued/1`,
  `transition/3`, `record_failure/2`.

## Deliverables

1. `Arbor.Curator.Content` (`apps/arbor_curator/lib/arbor/curator/content.ex`):
   `prepare(snapshot_result, max_chars) :: %{title: t | nil, content_excerpt: binary}` —
   truncates content to `max_chars` (CURATE-10), tolerates missing title/content.
2. `Arbor.Actions.Curator.FetchBatch` (submodule in
   `apps/arbor_actions/lib/arbor/actions/curator.ex`) — Jido action
   `name: "curator_fetch_batch"`, schema `batch_size: [type: :integer, default: 10]`:
   - Selects via `Store.next_queued(batch_size)` (CURATE-12).
   - Per item: snapshot `item.canonical_url` through the seam module (below) with
     `include_links: false, include_forms: false, include_headings: false,
     max_content_length: config :arbor_curator, :max_content_chars`; on success,
     `Content.prepare/2` then `Store.transition(item, :fetched, prepared)`; on error,
     `Store.record_failure(item, reason)` (CURATE-11). One item's crash/error MUST
     NOT abort the others — wrap per-item work.
   - Returns `%{fetched: n, failed: n, remaining_queued: n}`.
   - **Snapshot seam:** resolve the fetch module from
     `Application.get_env(:arbor_actions, :curator_snapshot_module, Arbor.Actions.Web.Snapshot)`
     and call its `run/2`. Production default is the real Snapshot — this is the
     ONLY fetch path (CURATE-9).
   - **Egress declaration:** the batch fetches operator-submitted URLs, so declare
     the action honestly: `effect_class :network_egress`, worst-case tier
     (`:external_peer`), no single destination. If your reading of the
     authorization path (Read first, item 2) shows per-destination caps cannot be
     satisfied by a batch action, restructure to per-item authorization following
     what the code requires — do not weaken or bypass the egress check. Report
     which shape you shipped and why in the result summary.
   - `output_taint :untrusted` (fetched content), `taint_roles` consistent with Web.
3. Config default already present from CP-01 (`:max_content_chars`); add
   `config :arbor_actions, :curator_snapshot_module` only in test config.

## Tests

With a fake snapshot module (scripted `{:ok, %{title:, content:}}` / `{:error, _}`)
swapped in via the seam:

- `@tag spec: "CURATE-9"` — the seam's production default is
  `Arbor.Actions.Web.Snapshot` (assert the unset-env resolution); grep-style
  assertion that `arbor_curator` + the curator actions reference no other HTTP
  client (no `Req.`, `Finch.`, `:httpc`, `HTTPoison`, `Tesla` outside the seam
  default), mirroring the VOICE-5 test approach.
- `@tag spec: "CURATE-10"` — oversized fake content is stored truncated to
  `max_content_chars`; title stored when present, item transitions to `fetched`.
- `@tag spec: "CURATE-11"` — a failing item gets `retry_count` incremented + error
  recorded and stays `queued`; on the Nth (configured max) failure it transitions to
  `failed`; a batch of [ok, fail, ok] processes all three.
- `@tag spec: "CURATE-12"` — with 15 queued items and `batch_size: 10`, the 10
  oldest are attempted; non-`queued` items are never selected.

chosen (Deliverable 2) with the file:line of the authorization path that decided it.
