# CP-06 — Digest: renderer, `curator_digest` + `curator_mark_surfaced` actions, 06:20 pipeline

**Phase:** 1 · **Depends:** CP-04 · **Blocks:** — · **Spec:** CURATE-18, CURATE-19, CURATE-20, CURATE-21, CURATE-22 (digest third), CURATE-23 (digest third), CURATE-24 (digest signal)
**App:** `arbor_curator`, `arbor_actions`, `arbor_scheduler`.

## Goal

Assessed items become a morning report at `~/.arbor/reports/curator/YYYY-MM-DD.md`
at 06:20 UTC — ahead of the 06:30 `morning_digest.dot` concatenation and 06:45
synthesis, which then include the curator section with zero new delivery code.
Surfaced items never reappear.

## Read first

- `apps/arbor_scheduler/priv/scripts/morning_digest.sh` — the glob contract your
  report must satisfy (`$HOME/.arbor/reports/<topic>/YYYY-MM-DD.md`, UTC date).
- `apps/arbor_scheduler/priv/pipelines/current_trends.dot` — the
  build-path → LLM → `file_write` exec chain; your pipeline replaces the LLM node
  with the digest action and adds a conditional skip.
- `apps/arbor_orchestrator/lib/arbor/orchestrator/handlers/` — `gate_handler.ex` /
  `branch_handler.ex` (read both; pick whichever the codebase uses for
  skip-when-empty) and `file_write_handler.ex` vs the `file_write` action — follow
  whichever write path `current_trends.dot` actually uses.
- `apps/arbor_curator/lib/arbor/curator/store.ex` — `assessed_unsurfaced/0`,
  `transition/3`.

## Deliverables

1. `Arbor.Curator.Digest` (`apps/arbor_curator/lib/arbor/curator/digest.ex`) — pure:
   - `render(items, date) :: String.t()` producing (CURATE-19):
     `# Curator — YYYY-MM-DD`, then `## Must read` (verdict `must_read`, score
     desc, cap 5: title as link to canonical URL, summary, *why it matters*),
     `## Worth a skim` (verdict `skim`, cap 10, one line each: linked title —
     summary first sentence), `## Arbor integration ideas` (deduplicated
     `integration_ideas` across the items above, attributed by linked title), and a
     footer line: `N new · M surfaced · K filtered as noise` (`skip` verdicts =
     noise; they are surfaced-marked but not listed).
   - Renders ONLY assessment fields + canonical URLs — never `content_excerpt`
     (CURATE-19).
   - `report_path(date) :: String.t()` — `<reports_root>/curator/YYYY-MM-DD.md`,
     `reports_root` from `config :arbor_curator, :reports_root` (default
     `~/.arbor/reports`, expand `~`) (CURATE-18).
2. `Arbor.Actions.Curator.Digest` (submodule in `actions/curator.ex`) — Jido action
   `name: "curator_digest"`, no required params: loads `assessed_unsurfaced()`;
   when empty returns `%{written: false, item_ids: []}` and the pipeline MUST skip
   the write (CURATE-21); otherwise returns
   `%{written: true, path: ..., content: ..., item_ids: [...]}` for the downstream
   write node. No filesystem writes inside this action — the gated write node does
   that (keeps fs capability at the manifest boundary).
3. `Arbor.Actions.Curator.MarkSurfaced` (same file) — Jido action
   `name: "curator_mark_surfaced"`, schema `item_ids: [type: {:list, :string}]`:
   transitions each `assessed→surfaced` (CURATE-20; `transition/3` sets
   `surfaced_at` once per CURATE-8), emits `curator.digest.written` with
   `%{date:, count:}` (CURATE-24), returns `%{surfaced: n}`.
4. `apps/arbor_scheduler/priv/pipelines/curator_digest.dot` — start →
   exec `curator_digest` → skip-to-done when `written` is false → write node
   (path+content from context) → exec `curator_mark_surfaced` (item_ids from
   context) → done. Mark-surfaced runs ONLY after a successful write (CURATE-20).
   Same-day rerun overwrites the file; already-surfaced items are excluded by
   `assessed_unsurfaced()` so reruns are idempotent (CURATE-18).
5. `curator_digest.caps.json` — only `fs/write` under `<reports_root>/curator/**`
   (mirror the URI shape in `morning_digest.caps.json` /
   `current_trends.caps.json`) (CURATE-23).
6. Crontab entry: `{"20 6 * * *", Arbor.Scheduler.Workers.PipelineRunner, args: %{"pipeline_path" => "apps/arbor_scheduler/priv/pipelines/curator_digest.dot"}}`
   (CURATE-22; 06:20 < 06:30 concatenation).

## Tests

  (6th must-read omitted, 11th skim omitted), score ordering, ideas deduplicated,
  noise counted in footer but not listed; an item whose `content_excerpt` contains
  a sentinel string proves the sentinel never appears in output.
- `@tag spec: "CURATE-18"` — `report_path/1` yields `<tmp_root>/curator/2026-07-13.md`
  under a tmp `reports_root` config; pipeline-level (or action+write integration)
  test writes, rewrites same day, file overwritten not duplicated.
- `@tag spec: "CURATE-20"` — after digest+mark, items are `surfaced` with
  `surfaced_at`; a second digest run selects none of them.
- `@tag spec: "CURATE-21"` — with zero assessed items the action returns
  `written: false` and the pipeline test asserts no file was created.
- `@tag spec: "CURATE-22"` — pipeline test (house pattern): seeded assessed items →
  enqueue `curator_digest.dot` → file exists at the CURATE-18 path with the
  CURATE-19 header; validate task passes.
- `@tag spec: "CURATE-23"` — manifest-content assertion as in CP-05.
- `@tag spec: "CURATE-24"` — signals subscriber sees `curator.digest.written`.
