# PP-06 — Activator: registrations, grants, supervised signal hooks

**Phase:** B · **Depends:** PP-05, PP-02 · **Blocks:** PP-07, PP-09, PP-11 · **Spec:** PLUGIN-19, 20, 21, 22, 23, 27, 28
**App:** `apps/arbor_artifacts` (+ one additive API in `arbor_orchestrator`).

## Goal

Turn an installed artifact into live behavior — and reverse it cleanly. This is
where "plugins as nodes" becomes real: activation drives entries into the
EXISTING registries under the plugin namespace; nothing bespoke executes plugins.

## Deliverables

1. `Arbor.Artifacts.Activator` (`apps/arbor_artifacts/lib/arbor/artifacts/activator.ex`):
   - `activate(name, opts)` — entry must be `:installed`/`:inactive` with a
     verified envelope (`Arbor.Security.verify_artifact/2` — re-verify at
     activation, not just install). Then, in order, collecting applied effects
     into the receipt:
     a. **Capability grants** for `requires_capabilities` to the artifact's
        principal (`grant/1`); record grant ids.
     b. **Actions:** `ActionRegistry.register(entry.name, module, %{category:
        :plugin, artifact: name})` — entry names are already `"<name>."`-prefixed
        (PP-01 validation). Modules resolved via `String.to_existing_atom` —
        pre-built code must be compiled in; a missing module is an activation
        failure, never a dynamic load.
     c. **Handlers:** `Orchestrator.Handlers.Registry.register(type, module)`.
     d. **Templates:** overlay registration (Deliverable 4).
     e. **Signal hooks:** start one `Arbor.Artifacts.HookRunner` child per hook
        under `HookSupervisor` (Deliverable 3); record child ids + sub ids.
     f. **UI:** record the manifest's ui section into the registry entry
        (consumed by PP-10; no dashboard dep from this app).
     g. `Registry.set_status(name, :active, actor)`.
   - `deactivate(name, opts)` — reverse receipt order: terminate hook children,
     deregister actions/handlers, remove template overlays, revoke
     activation-time grants, clear ui, `:inactive`.
   - **Idempotence/rollback (PLUGIN-23):** activating an `:active` artifact is a
     no-op `{:ok, :already_active}`. Any step failure rolls back the already-
     applied steps of THIS attempt (receipt-driven), sets `:failed` with
     `status_reason`, returns the error.
   - **Dependents guard (PLUGIN-28):** `deactivate` checks
     `Registry.provider_of/1` consumers: if another `:active` artifact's
     `requires_capabilities` is satisfied ONLY by this artifact's
     `provides_capabilities`, refuse `{:error, {:dependents, [...]}}` unless
     `force: true`; forced deactivation emits `artifact.deactivated` with
     `forced: true` and dependent names.
2. Facade verbs on `Arbor.Artifacts`: `activate/2`, `deactivate/2`.
3. `Arbor.Artifacts.HookRunner` — GenServer taking
   `%{artifact, pattern, module}`; on init `Arbor.Signals.subscribe(pattern,
   &module.handle_signal/1)` keeping the sub id; on terminate `unsubscribe`.
   The hook module contract: `handle_signal(signal) :: :ok | {:error, term()}`
   — define `Arbor.Artifacts.SignalHook` behaviour here (library-specific, NOT
   in contracts).
4. Orchestrator additive API (small, separate commit within the branch):
   `TemplateRegistry.register_overlay(source_id, dir)` +
   `remove_overlay(source_id)` + `list/0` including overlay templates
   (name-prefixed `"<source_id>."`). Keep file-based core untouched;
   overlays in a `persistent_term` or Agent — match the module's existing style.

## Tests

Fixture artifact `test/support/fixtures/artifacts/demo_plugin/` (compiled test
modules under `test/support/`, manifest referencing them, signed with a test key):
- `@tag spec: "PLUGIN-19"` — activation registers `demo.echo` action resolvable
  via `ActionRegistry.resolve_by_name("demo.echo")`; attempts to register a
  non-prefixed name fail activation (fixture variant).
- `@tag spec: "PLUGIN-20"` — deactivate leaves no trace: action unresolvable,
  handler unregistered, overlay gone, grants revoked (`list_capabilities`),
  hook process down, registry ui empty.
- `@tag spec: "PLUGIN-21"` — hook runs under HookSupervisor; killing the runner
  triggers restart + resubscribe; deactivation terminates it and the
  subscription no longer fires (emit after deactivate, assert no callback).
- `@tag spec: "PLUGIN-22"` — grants exist only while active; artifact principal
  has exactly the declared capabilities (no more).
- `@tag spec: "PLUGIN-23"` — double-activate no-op; injected failure at step (c)
  rolls back (a)+(b).
- `@tag spec: "PLUGIN-27"` — a fixture requiring `demo:provides` activates when
  provider active, fails with a capability-unsatisfied error when not.
- `@tag spec: "PLUGIN-28"` — deactivating the provider with an active dependent
  refuses; `force: true` succeeds with the flagged signal.
