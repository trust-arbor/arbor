# PP-04 — Revocation + enforce-by-default

**Phase:** A · **Depends:** PP-03 · **Blocks:** PP-07 · **Spec:** PLUGIN-10, 12 (revoked half)
**App:** `apps/arbor_security` (L2) + `apps/arbor_orchestrator` (L7) config flip.

## Goal

Revoke an artifact (or a signing key) and have every verification fail from that
moment; then flip Engine verification to `:enforce` as the default. Completes the
dot-signing-and-verification planned item's P2/P3.

## Read first

- `apps/arbor_security/lib/arbor/security/capability_store.ex` — the
  ETS-front + `Arbor.Persistence.BufferedStore` durability pattern to copy
- PP-02's `Arbor.Security.Artifact.Signer` (as merged)
- PP-03's `ArtifactVerification` + config switch (as merged)
- `apps/arbor_security/lib/arbor/security.ex` facade

## Deliverables

1. `Arbor.Security.Artifact.RevocationStore`
   (`apps/arbor_security/lib/arbor/security/artifact/revocation_store.ex`):
   GenServer, ETS hot table + BufferedStore persistence (store name
   `:arbor_security_artifact_revocations`). Records:
   `%{scope: :artifact | :key, name: String.t() | nil, version: String.t() | nil,
   key_id: String.t() | nil, reason: String.t(), revoked_by: String.t(),
   revoked_at: DateTime.t()}`. API: `revoke/1`, `revoked?/1` (accepts
   `%SignatureEnvelope{}` — matches artifact name+version OR key_id),
   `list/0`. Supervised in the security app's tree.
2. Facade: `Arbor.Security.revoke_artifact/2` (requires a valid
   `SigningAuthority`, same validation approach as PP-02 signing),
   `artifact_revoked?/1`. `verify_artifact/2` (from PP-02) now checks
   `revoked?/1` FIRST and returns `{:error, :revoked}`.
3. Mix task `mix arbor.artifact.revoke <name> <version> --reason "..."` and
   `--key <key_id>` variant (revokes everything signed by a key). Lists current
   revocations with `--list`.
4. Engine default flip: `:arbor_orchestrator, :artifact_verification` default
   becomes `:enforce`. Prereq check inside this packet: run
   `mix arbor.pipeline.sign_stdlib` (PP-03) so the committed tree boots signed;
   CI/dev boot must pass with enforcement on.
5. Version pinning: `ArtifactVerification.verify/2` (PP-03) additionally rejects
   an envelope whose `artifact_version` mismatches a version recorded in its
   manifest argument (defense against envelope swapping between versions).

## Tests

`apps/arbor_security/test/arbor/security/artifact/revocation_store_test.exs` +
orchestrator additions:
- `@tag spec: "PLUGIN-10"` — revoke → `verify_artifact` fails immediately;
  restart the store (stop/start GenServer with same persistence) → still revoked.
- `@tag spec: "PLUGIN-12"` — Engine (`:enforce`) refuses a run whose artifact was
  revoked mid-session (revoke between two runs, second refused), signal emitted
  with `:revoked`.
- Key-scope revocation kills all artifacts signed by that key (two-artifact
  fixture).
- Boot smoke: with default config, orchestrator app starts and a stdlib pipeline
  (e.g. `stdlib/llm-chain.dot`) runs — proving sidecars + enforcement coexist.

## Acceptance

- `./bin/mix compile --warnings-as-errors`; full orchestrator + security suites
  green **with `:enforce` as default**.
- `mix arbor.artifact.revoke` round-trip demonstrated in a task test.

## Out of scope

Registry status sync (`:revoked` status in arbor_artifacts — PP-05 consumes the
signal), marketplace revocation distribution (PP-15). No new Engine seams beyond
the PP-03 hook.
