# PP-07 — Install/uninstall as stdlib DOT pipelines + receipts

**Phase:** B · **Depends:** PP-06, PP-03 (PP-04 for enforce) · **Blocks:** PP-08, PP-09, PP-12 · **Spec:** PLUGIN-24, 25, 26
**App:** `apps/arbor_orchestrator` (pipeline specs) + `apps/arbor_artifacts` (actions + mix tasks).

## Goal

Installation is itself a governed pipeline — reviewable, signed, budgeted — not
imperative library code. The receipt is the uninstall guide and audit trail.

## Deliverables

1. Stdlib pipelines (signed via `mix arbor.pipeline.sign_stdlib`):
   - `apps/arbor_orchestrator/specs/pipelines/stdlib/install-artifact.dot`:
     `start → verify (artifact.verify action) → admission_gate (branch: shared?
     → PP-08 consult node, else skip) → stage (artifact.stage) → activate
     (artifact.activate) → write_receipt (artifact.write_receipt) → done`, with
     `condition="outcome=fail"` edges routing every step to a `refuse` exit that
     emits `artifact.failed`. Graph attrs: `goal`, `required_capabilities`
     (installation itself needs only artifact-facade capabilities).
   - `.../stdlib/uninstall-artifact.dot`: `start → read_receipt → deactivate →
     remove_files (artifact.remove_staged) → finalize (registry delete) → done`;
     missing receipt routes to `refuse` unless input `force=true` (then the
     forced path tags the emitted signal, PLUGIN-25).
2. Jido actions in `apps/arbor_artifacts/lib/arbor/artifacts/actions.ex`
   (registered at boot under `artifact.*` names — post-lock namespaced,
   `category: :artifact`): `Verify`, `Stage`, `Activate`, `Deactivate`,
   `WriteReceipt`, `ReadReceipt`, `RemoveStaged`. Thin wrappers over
   `Arbor.Artifacts` + `Arbor.Security` facades; taint_roles on all inputs
   (bundle paths are `:control`).
   - `Stage` copies bundle payload into the managed dir
     `Arbor.Artifacts.Config.artifacts_dir()` (default `priv/artifacts/<name>/`
     under arbor_artifacts, config-overridable) — **confinement (PLUGIN-26):**
     every destination path must resolve inside `artifacts_dir()/<name>/`;
     reject traversal/absolute/symlink escapes — use the existing
     `Arbor.Common.SafePath.resolve_within/2`
     (`apps/arbor_common/lib/arbor/common/safe_path.ex`), do not hand-roll.
   - `WriteReceipt` persists the Receipt (PP-01) BOTH into the registry entry and
     as `artifacts_dir()/<name>/receipt.json`.
3. Mix tasks in `apps/arbor_artifacts/lib/mix/tasks/arbor/artifact/`:
   `mix arbor.artifact.install <bundle_dir>` and
   `mix arbor.artifact.uninstall <name> [--force]` — run the corresponding
   pipeline via the Engine (see how `mix arbor.pipeline.run` invokes it),
   passing bundle path / name as pipeline input; print receipt summary.
4. `Arbor.Artifacts.install/2` + `uninstall/2` facade verbs delegating to the
   same pipeline execution path (one implementation, two entrances).

## Tests

Integration (`:integration` where the Engine runs; use the demo fixture from
PP-06 packaged as a bundle dir):
- `@tag spec: "PLUGIN-24"` — install pipeline: happy path ends `:active` with
  receipt; tampered bundle refuses at `verify` with NO side effects (no staged
  files, no registry entry, no grants — assert all three).
- `@tag spec: "PLUGIN-25"` — receipt lists every effect; uninstall reverses all
  of them (filesystem + registries + grants); uninstall without receipt refuses;
  `--force` proceeds + signal carries `forced: true`.
- `@tag spec: "PLUGIN-26"` — malicious manifest with `../escape` payload path is
  rejected at manifest validation AND a crafted stage destination outside the
  managed dir is refused (belt and suspenders).
- Unit: each action `:fast` with fakes.
