# PP-12 — Bundle format: package, export, import

**Phase:** D · **Depends:** PP-07 · **Blocks:** PP-13, PP-14, PP-15 · **Spec:** PLUGIN-33
**App:** `apps/arbor_artifacts`.

## Goal

A portable, verifiable bundle file so artifacts can move between installations —
deterministic pre-built payloads as the default distribution unit. Removes the
PLUGIN-33 `(planned)` marker.

## Read first

- PP-07 `Stage` action + `artifacts_dir()` confinement (as merged)
- PP-01 Manifest payload digests; PP-02 envelope; PP-04 revocation check
- `apps/arbor_persistence/lib/mix/tasks/arbor/backup.ex` (or nearest) — existing
  archive-handling conventions in the repo, if any (grep `:erl_tar` /
  `:zip` across apps/ and follow precedent; `:erl_tar` with `:compressed` is the
  default choice absent precedent)

## Deliverables

1. Bundle layout (documented in `Arbor.Artifacts.Bundle` moduledoc):
   ```
   <name>-<version>.arbor-artifact   (gzipped tar)
     manifest.json
     manifest.sig.json               (SignatureEnvelope)
     payload/<relative paths from manifest>
     src/*.dot                       (optional generative sources, signed sidecars)
   ```
2. `Arbor.Artifacts.Bundle`:
   - `package(bundle_dir, out_path)` — validates manifest, re-hashes payload
     against digests, requires envelope present + verifying, writes
     deterministic tar (sorted entries, fixed mtime/uid — byte-reproducible:
     same input dir ⇒ same file hash).
   - `inspect(path)` — safe listing WITHOUT extraction (entry names validated:
     no absolute paths, no `..`, no links; size ceiling from config
     `:arbor_artifacts, max_bundle_bytes`, default 50MB).
   - `import(path, opts)` — inspect → extract to a temp staging dir inside
     `artifacts_dir()/.staging/` → verify manifest digests + signature +
     revocation (`Arbor.Security`) → hand the staged dir to the PP-07 install
     pipeline. ANY failure cleans the staging dir; nothing touches registries or
     final dirs before verification passes (PLUGIN-33's ordering).
3. Mix tasks: `mix arbor.artifact.package <bundle_dir> [-o out]`,
   `mix arbor.artifact.import <file>` (runs full install incl. admission branch).
4. Export: `mix arbor.artifact.export <name>` — re-package an installed artifact
   from `artifacts_dir()/<name>/` + registry manifest/envelope (round-trip:
   export → import elsewhere).

## Tests

- `@tag spec: "PLUGIN-33"` — import of a valid bundle installs + activates
  (demo fixture); tampering with one payload byte inside the tar → import fails
  at verify, staging cleaned, registry untouched; revoked artifact → same.
- Determinism: package twice ⇒ identical sha256.
- Hostile-archive suite: entries with `../`, absolute path, symlink, oversize —
  all rejected at `inspect` (fixtures constructed with `:erl_tar` directly).
- Round-trip: install (PP-07) → export → uninstall → import → same receipt
  registrations.
