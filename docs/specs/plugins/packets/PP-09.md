# PP-09 — Browser plugin: first real migration (actions only)

**Phase:** C · **Depends:** PP-07 · **Blocks:** — (1.0 exit A) · **Spec:** PLUGIN-19, 20, 22, 24, 25 (as exercised end-to-end on real code)
**App:** `apps/arbor_actions` (bundle-ification) + `apps/arbor_artifacts` fixtures.

## Goal

The first non-fixture plugin: the 26 `Arbor.Actions.Browser.*` actions leave the
hardcoded core catalog and become an installable, deactivatable artifact. Proves
the channel on code users actually run, without UI complexity.

## Read first

- `apps/arbor_actions/lib/arbor/actions/browser/` — all 7 files (session,
  navigation, interaction, query, content, sync, evaluate) + `browser.ex` helper
- `apps/arbor_actions/lib/arbor_actions.ex` — `list_actions/0` `browser:` group
  (grep `browser:` around line 1274) and how the Registrar consumes this map
- `apps/arbor_orchestrator/lib/arbor/orchestrator/registrar.ex` —
  `register_actions/1` + `lock_core` ordering (browser must register AFTER lock,
  via activation)
- PP-06 Activator, PP-07 install pipeline + `artifacts_dir()` convention
- `apps/arbor_actions/lib/arbor/actions/browser/navigation.ex` — `taint_roles/0`
  style (capability enforcement stays with Engine middleware — do NOT add
  self-checks)

## Deliverables

1. Bundle manifest at `apps/arbor_actions/priv/artifacts/browser/manifest.json`:
   `kind: plugin`, `name: "browser"`, version `1.0.0`,
   `requires_capabilities`: the egress/web capability URIs the Engine's
   CapabilityCheck expects for these actions (derive from existing capability
   URIs — grep `arbor://` usage for web/egress; do not invent new URI shapes
   without matching the existing scheme), `provides_capabilities`:
   `["action:browser"]`, registrations.actions listing all 26 actions as
   `browser.<action>` names → existing module strings. Payload list: the 8
   source files with digests (they stay compiled in-repo at 1.0; payload digests
   still pin content). Signed sidecar committed
   (`mix arbor.artifact.sign`).
2. Core catalog change: remove the `browser:` group from
   `Arbor.Actions.list_actions/0` so the Registrar no longer registers browser
   actions as core. Keep the modules compiled where they are (physical extraction
   is the umbrella-repackaging effort's job — reference it in a code comment).
3. Boot activation: `:arbor_artifacts, default_active: ["browser"]` — on app
   start, `Arbor.Artifacts.Bootstrap` (new, small) installs-if-absent (from the
   priv bundle dir, running the install pipeline) and activates each configured
   default so existing behavior is unchanged out of the box.
4. Name continuity: browser actions were dot-named in the core map; confirm the
   activation-registered names match what pipelines/DOTs already reference (grep
   `.dot` specs + `action_index.json` for `browser.`); fix references if any
   drift. Note findings in the result summary.
5. Deactivation story: `Arbor.Artifacts.deactivate("browser")` makes
   `ActionRegistry.resolve_by_name("browser.navigate")` return
   `{:error, :not_found}`; a pipeline using it fails with the standard
   unknown-action error (no special-casing).

## Tests

- Integration: fresh boot with defaults → `browser.navigate` resolves; with
  `default_active: []` → it does not (proving core no longer carries it).
- `@tag spec: "PLUGIN-19"`/`"PLUGIN-20"` on real modules: activate/deactivate
  round-trip of the browser artifact (resolve → not_found → resolve again on
  re-activate).
- `@tag spec: "PLUGIN-22"` — while active, the artifact principal holds exactly
  the manifest's `requires_capabilities`.
- `@tag spec: "PLUGIN-24"`/`"PLUGIN-25"` — install-from-priv-bundle produces a
  receipt whose registrations match the 26 actions; uninstall reverses (then
  reinstall for suite hygiene, or scope to a sandboxed artifacts_dir via config).
- Existing browser action unit tests keep passing untouched (they test module
  behavior, not registration).

## Acceptance

- `./bin/mix compile --warnings-as-errors`; full umbrella suite green with
  default config (browser active via bootstrap).
- Demonstrated in test: no core registration of `browser.*` when artifact
  inactive.

## Out of scope

Physical move of browser modules out of arbor_actions (umbrella-repackaging
owns that), UI (PP-10/11), jido_browser dependency changes, capability URI
redesign. Do not migrate any other action group in this packet.
