# PP-11 — Observability plugin: signals/events/monitor/telemetry views

**Phase:** C · **Depends:** PP-10, PP-06 · **Blocks:** — (1.0 exit B) · **Spec:** PLUGIN-31, 32 (real migration), 20 (UI leg)
**App:** `apps/arbor_dashboard` (bundle subtree) + manifest.

## Goal

First real UI migration: the four developer-observability views leave the core
nav/router and become the `observability` artifact (~1,270 LOC + cores out of
core UX). Deactivate → they vanish; core dashboard (chat, agents, memory,
landing, settings…) is untouched.

## Read first

- PP-10 as merged (dispatch + nav mechanics)
- `apps/arbor_dashboard/lib/arbor_dashboard/live/{signals_live.ex,events_live.ex,monitor_live.ex,telemetry_live.ex}`
  + their cores: `cores/{signals_core.ex,events_core.ex,monitor_core.ex,telemetry_core.ex}`
  and `components/telemetry_component.ex`
- `apps/arbor_dashboard/lib/arbor_dashboard/nav.ex` — the four entries to remove
- `apps/arbor_dashboard/lib/arbor_dashboard/router.ex` — the four routes to remove

## Deliverables

1. Bundle subtree (code stays in this app at 1.0; extraction-ready layout):
   move the four LiveViews + their cores/components into
   `apps/arbor_dashboard/lib/arbor_dashboard/plugins/observability/`
   (namespace `Arbor.Dashboard.Plugins.Observability.*`; update aliases).
   **Isolation rule (extraction-ready):** no module OUTSIDE the subtree may
   reference a module inside it — enforced by a test (grep-based like the PP-05
   layering guard, or a compile-tracer check if one exists in the repo).
2. Manifest `apps/arbor_dashboard/priv/artifacts/observability/manifest.json`:
   `name: "observability"`, registrations.ui:
   `nav: [Signals, Events, Monitor, Telemetry]` entries with
   `href: "/x/observability/<view>"`, `views: {"/observability/signals" =>
   "...SignalsLive", ...}`; `requires_capabilities` for what the cores read
   (match whatever authorization the views perform today — check
   `signal_subscription.ex` usage; likely none beyond signal read). Signed
   sidecar committed.
3. Router/nav cleanup: remove `/signals`, `/events`, `/monitor`, `/telemetry`
   routes and their `@nav_entries` — they now exist only via the artifact
   (default-active, PP-09's `default_active: ["browser", "observability"]`).
4. Redirects: add plain `get` redirects `/signals → /x/observability/signals`
   etc. (controller-level, cheap, keeps old links/bookmarks working). These
   redirect regardless of artifact status; the dispatch view handles inactive.
5. Views must render correctly under the dispatch route: fix any assumptions
   about their own `@live_action`/path (`handle_params` paths, `push_patch`
   targets) — subtree-internal changes only.
