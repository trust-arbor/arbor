# PP-02 — Artifact signing in `arbor_security`

**Phase:** A · **Depends:** PP-01 · **Blocks:** PP-03, PP-04, PP-07, PP-12 · **Spec:** PLUGIN-7, 8, 9 (+ PLUGIN-2 signing side)
**App:** `apps/arbor_security` (L2), small mix tasks.

## Goal

Sign and verify artifacts (manifests + DOT payloads) through the `Arbor.Security`
facade: Ed25519, per-signer keys from `SigningKeyStore`, detached envelopes.
No raw keys outside `arbor_security`; no closures.

## Deliverables

1. `Arbor.Security.Artifact.Signer`
   (`apps/arbor_security/lib/arbor/security/artifact/signer.ex`):
   - `sign_manifest(manifest, key_id)` → `{:ok, SignatureEnvelope.t()} | {:error, term()}` —
     canonical_encoding → sha256 → `Crypto.sign/2` with the private key fetched
     inside this module from `SigningKeyStore.get_keypair(key_id)`. Key never
     returned to callers.
   - `verify_manifest(manifest, envelope)` → `:ok | {:error, :signature_invalid |
     :digest_mismatch | :unknown_key | :algorithm_unsupported}` — recompute
     canonical encoding + sha256, compare to envelope, `Crypto.verify/3` with the
     public key resolved from `key_id`.
   - `sign_payload_digest(digest_sha256, key_id)` / `verify_payload_digest/3` —
     for DOT payload bytes whose digest the caller computed (see 3).
2. Facade additions in `Arbor.Security`
   (`apps/arbor_security/lib/arbor/security.ex`): `sign_artifact/2`,
   `verify_artifact/2`, `artifact_signing_available?/0` — thin delegation to
   `Artifact.Signer`, following the facade's existing doc/`@spec` style. Signing
   MUST require a live `SigningAuthority` (accept it as an argument and validate
   via the broker before signing) so callers cannot mint signatures without
   authority. Choose the exact validation call by reading the broker; if no
   suitable check exists, add a minimal `authority_valid?/1` to the broker rather
   than bypassing it.
3. **Layering note (binding):** `arbor_security` (L2) MUST NOT depend on the
   orchestrator (L7). It signs/verifies *digests and canonical binaries* handed to
   it. Whoever has a `%Graph{}` serializes canonically
   (`DotSerializer.serialize(graph, strip_internal: true)`) and passes bytes or
   digest down. Document this in the Signer moduledoc.
4. Key management: `key_id` convention `"artifact:<principal>"`;
   `Arbor.Security.ensure_artifact_signing_key/1` creates the keypair via
   `SigningKeyStore.put_keypair/3` if absent, returns key_id + public key.
5. Mix tasks (nested-dir style, in `apps/arbor_security/lib/mix/tasks/arbor/artifact/`):
   - `mix arbor.artifact.sign <manifest.json> --key <key_id>` — validates manifest
     (PP-01), verifies payload digests against files on disk, writes
     `<name>-<version>.sig.json` envelope next to the manifest.
   - `mix arbor.artifact.verify <manifest.json> <sig.json>` — full check incl.
     payload digest re-hash; exit 1 + reason on failure.

## Tests

`apps/arbor_security/test/arbor/security/artifact/signer_test.exs` (`:fast`):
- `@tag spec: "PLUGIN-7"` — sign→verify round-trip; verify fails after any
  manifest field mutation; private key not present in envelope or any return
  value (assert on struct + Jason output).
- `@tag spec: "PLUGIN-9"` — envelope is detached: payload files untouched
  (tmp-dir fixture), envelope carries digest not content.
- `@tag spec: "PLUGIN-2"` — same manifest built with different input key order
  signs to identical signature.
- Facade: signing without a valid authority returns error (broker fake or
  test-fixture authority — see how existing security tests build authorities;
  never a live OIDC call).
- Mix task test: sign then verify a tmp fixture bundle; corrupted payload file
  fails verify with `:digest_mismatch`.

`@tag spec: "PLUGIN-8"` lands in PP-03 (needs Engine-side serialize); note this
in a test comment here.
