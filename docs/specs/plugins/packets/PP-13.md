# PP-13 — Generative-path guards: AST static gate (post-1.0 flag)

**Phase:** D · **Depends:** PP-12 · **Blocks:** — · **Spec:** PLUGIN-35, 36 (gate half), 37 (envelope half)
**App:** `apps/arbor_artifacts` (gate) — flag-gated, OFF by default.

## Goal

The layer-1.5 gate from the 2026-07-04 decision: generated Elixir is statically
screened BEFORE any compile, because Elixir macros execute at compile time —
`mix compile` of untrusted source IS code execution. This packet ships the gate
and the refuse-without-isolation policy; actual isolated execution is PP-14.

## Deliverables

1. `Arbor.Artifacts.AstGate` (`apps/arbor_artifacts/lib/arbor/artifacts/ast_gate.ex`):
   - `scan(source_string, opts)` → `{:ok, report} | {:error, violations}` —
     `Code.string_to_quoted` (never `Code.eval_*`) + `Macro.prewalk` deny-walk.
   - Deny list (each violation carries AST location + category):
     `System`/`:os`/`:erlang.halt`/`Port`/`Code`/`Node`/`:net_kernel`,
     `Arbor.Security.*` internals (anything below the facade —
     `Crypto`, `SigningKeyStore`, `CapabilityStore`, broker modules),
     `String.to_atom`/`Module.concat` with non-literal args (dynamic atoms),
     `apply/3` + `Kernel.send` to non-literal targets,
     side-effecting module attributes (`@on_load`, `@before_compile`,
     `@after_compile`, `@compile` callbacks), `use`/`import`/`require` of
     modules outside an allowlist (config
     `:arbor_artifacts, ast_gate_allowed_deps`, seeded with `Jido.Action`,
     `Arbor.Contracts.*`, stdlib-safe modules),
     `defimpl` for protocols owned by security/orchestrator,
     process dictionary writes, `:ets` access to non-owned tables (any literal
     table atom not prefixed by the artifact name).
   - Fail-closed on parse errors and on constructs the walker can't classify
     (unknown-is-denied, with category `:unclassified`).
   - `scan_bundle(staging_dir)` — every `.ex` under `payload/` and every
     generated file a generative pipeline declares as output.
2. Policy wiring: install pipeline gains a `generative?` branch — bundles whose
   manifest provenance marks `source: "generative"` (or containing `.ex` in
   `src/`-declared outputs) MUST pass `scan_bundle` before any compile step,
   and MUST refuse when `:arbor_artifacts, :artifact_isolation` is `:none`
   (PLUGIN-36's gate half; the isolated compile itself is PP-14). Config
   `generative_installs: :disabled | :enabled` — default `:disabled` (post-1.0).
3. Report format: violations grouped by file with severity; persisted into the
   registry entry on refusal (`status_reason`) so refusals are auditable.

## Tests

(`:fast`, pure — no compilation of hostile source anywhere in the suite):
- `@tag spec: "PLUGIN-35"` — table-driven hostile corpus: each deny-list
  category has ≥1 fixture that is caught (System.cmd, `:os.cmd`, @on_load,
  dynamic `String.to_atom(var)`, `Code.eval_string`, security-internal alias,
  ets on foreign table, non-allowlisted `use`); benign Jido action fixture
  passes clean.

  (fail-closed proof).
- `@tag spec: "PLUGIN-36"` — generative-marked bundle with `artifact_isolation:
  :none` refuses BEFORE any gate/compile work (policy ordering assertion).
- `@tag spec: "PLUGIN-37"` — a generative bundle's outputs route through the
  same install pipeline (verify → gate → admission) — assert the pipeline path
  taken, with compile/test nodes mocked pending PP-14.
- Property sanity: scan never raises (StreamData over small random ASTs;
  errors become `{:error, _}`).
