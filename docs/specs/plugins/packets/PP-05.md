# PP-05 — New app `apps/arbor_artifacts` + Registry

**Phase:** B · **Depends:** PP-01 · **Blocks:** PP-06..PP-15 · **Spec:** PLUGIN-16, 17, 18 (partial: catalog + signals)
**App:** new `apps/arbor_artifacts` (L8).

## Goal

The artifact catalog — Ring 0's one genuinely new component. Tracks installed
artifacts (manifest, envelope, status, receipt), persists them, emits lifecycle
signals. Read/query surface only; activation lands in PP-06.

  BufferedStore pattern (copy this, not RegistryBase: this is a lifecycle

## Deliverables

1. `apps/arbor_artifacts/` umbrella app, `Arbor.Artifacts.Application`
   supervising `Arbor.Artifacts.Registry` (+ a `DynamicSupervisor` named
   `Arbor.Artifacts.HookSupervisor`, children come in PP-06). Umbrella deps,
   exactly: `arbor_contracts, arbor_common, arbor_signals, arbor_security,
   arbor_persistence, arbor_consensus, arbor_actions, arbor_orchestrator` (all
   `in_umbrella: true`) + `jason`. That lands it at L8 (verify with the
   hierarchy drift-guard test).
2. `Arbor.Artifacts.Registry` (GenServer):
   - Entry: `%{manifest, envelope, status, receipt, installed_at, updated_at,
     status_reason}` keyed by `name` (one installed version per name at 1.0;
     document this constraint).
   - API: `put_installed/3` (manifest, envelope, receipt-or-nil),
     `get/1`, `list/0`, `list_by_status/1`, `set_status/3` (validates via
     `Status.valid_transition?/2`), `update_receipt/2`, `active?/1`,
     `provider_of/1` (capability string → active artifact name, for PP-06/28).
   - Persistence: ETS hot table + `Arbor.Persistence.BufferedStore`
     (store `:arbor_artifacts_registry`); state restored on init.
   - Signals: every successful transition emits
     `artifact.<installed|activated|deactivated|failed|revoked>` with
     `%{name, version, actor}` via `Arbor.Signals.emit`.
   - Revocation sync: subscribe (supervised in the app's tree, PLUGIN-21 style —
     an owned GenServer, not a bare closure) to the PP-04 security signal for
     revocations and flip matching entries to `:revoked`.
3. `Arbor.Artifacts` facade module: thin, documented delegation (get/list/
   active?/list_by_status). Lifecycle verbs (install/activate/…) arrive in
   PP-06/PP-07 — leave `@doc` stubs out; do not pre-declare.
4. Config: `:arbor_artifacts, bundle_dirs: []` (used from PP-06 on), read via a
   `Arbor.Artifacts.Config` module.
